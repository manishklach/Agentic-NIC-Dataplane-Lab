# v0.1.0 Release Notes

`v0.1.0` is the first public release of `Agentic-NIC-Dataplane-Lab`.

This release establishes the repo as a Linux-first reference lab for:

- tri-path networking for agentic AI workloads
- `AF_XDP`, `io_uring`, and `RDMA` starter paths
- benchmark framing for agent-shaped traffic
- bounded autonomous NIC architecture concepts
- safety, auditability, and tenant-aware controls

## Highlights

### 1. Tri-path architecture is now clearly defined

The repo documents a practical split between:

- `Path A`: kernel TCP plus `io_uring`-based optimization
- `Path B`: `AF_XDP` for selected hot queues
- `Path C`: `RDMA` for bulk east-west movement

This is reflected in:

- `README.md`
- `docs/reference-architecture.md`
- `docs/networking-for-agentic-ai-blog.md`

### 2. Starter build system and CI are in place

The repo now includes:

- a root `Makefile`
- `BUILDING.md`
- GitHub Actions compile checks

The build flow covers:

- `AF_XDP`
- `io_uring`
- `RDMA`
- XDP BPF object compilation

The build system was also hardened for portability:

- `io_uring` sample compatibility with older `liburing`
- multiarch include path support for BPF builds
- `libxdp`-aware AF_XDP build logic for Ubuntu-style packaging

### 3. AF_XDP path has moved beyond a bind-only stub

The `AF_XDP` sample now includes a more realistic starter path with:

- UMEM setup
- fill-ring prepopulation
- RX polling
- frame recycling
- TX completion recycling
- a helper loader script

Files:

- `src/af_xdp/main.c`
- `src/af_xdp/xdp_pass.c`
- `tools/af_xdp_load.sh`

This is still a starter implementation, not a production dataplane, but it now teaches the right lifecycle rather than stopping at socket bind.

### 4. Benchmarking artifacts are now repo-native

The repo includes:

- a JSON-emitting benchmark harness
- an illustrative Intel E810 baseline result artifact
- a matplotlib plotting script

Files:

- `scripts/benchmark-matrix.sh`
- `results/e810-baseline-2026-05-08.json`
- `tools/plot_e810_baseline.py`

This gives the project a stronger measurement story and a reusable results format.

### 5. Agentic NIC control concepts are first-class docs now

The repo now goes beyond dataplane transport comparison and defines a more differentiated architecture around:

- `Intent -> Agent -> Guardian -> Dataplane -> Audit`
- bounded autonomy
- deterministic fallback
- reasoning logs
- tenant-aware quotas

Files:

- `docs/agentic-nic-architecture.md`
- `docs/safety-and-guardrails.md`
- `docs/reasoning-log-design.md`
- `docs/multi-tenant-agent-quotas.md`

### 6. Release blockers are explicitly documented

This release also makes the open risks clear instead of hiding them.

The repo now explicitly calls out the need to:

- prove `Path B` is not worse than `Path A` for sub-`512 B` RPCs
- demonstrate that guardian intervention does not violate tail-latency SLOs
- define a concrete threat model for who can read reasoning logs

Supporting additions:

- `docs/audit-layer-threat-model.md`
- `tools/bpftrace/guardian_preemption.bt`
- `tools/bpftrace/guardian_tail_latency_guard.bt`

## What Is Stable In This Release

- overall repo structure
- architecture framing
- build and CI entry points
- benchmark taxonomy
- starter code layout for all three paths
- autonomous NIC conceptual model

## What Is Still Early

- the `AF_XDP` path still needs a fuller end-to-end traffic demo and loader plumbing around redirect maps
- the `io_uring` sample is still a focused starter, not a complete zero-copy receive engine
- the `RDMA` sample still needs the full `RESET -> INIT -> RTR -> RTS` flow and peer exchange logic
- the benchmark harness still needs deeper automation around workload generation and aggregation
- the baseline JSON artifact is illustrative and should be replaced by real measured hardware runs

## Suggested Next Steps After v0.1.0

1. Complete the `AF_XDP` queue-redirection path with `XSKMAP` integration and a reproducible receive demo.
2. Add full RDMA queue-pair bring-up and a small two-endpoint benchmark.
3. Expand the benchmark harness to produce real measurement runs for sub-`512 B` traffic.
4. Validate guardian intervention behavior with actual tracing and latency histograms on a live prototype.
5. Decide whether to split the repo into a “practical dataplane lab” track and a “agentic NIC control architecture” track, or keep them unified.
